# API Env / `wrangler types` secrets

Status: investigate and fix properly. Hand-patched for now so typecheck passes.

## Problem

`apps/api/src/env.ts` is `Cloudflare.Env` from `worker-configuration.d.ts`, regenerated by:

```bash
pnpm --filter @strengthsync/api types   # → wrangler types
```

Wrangler only emits **secret** fields on `Env` when `apps/api/.dev.vars` exists. That file is gitignored. Regenerating without it drops:

- `BASIC_AUTH_USERNAME` / `BASIC_AUTH_PASSWORD`
- `OPENAI_API_KEY`
- (legacy, retired in the Cloudflare Workflows migration) `INTERNAL_API_SERVICE_SECRET`, `WORKFLOW_API_URL` / `WORKFLOW_SERVICE_SECRET`

…and `src/index.ts` fails typecheck (`Property '…' does not exist on type 'Env'`).

`.dev.vars.example` is not enough: commented legacy lines are also ignored even if you copy the example.

## Current workaround

The required secret fields were restored by hand in `__BaseEnv_Env` at the top of `apps/api/worker-configuration.d.ts`. Next `wrangler types` without `.dev.vars` will wipe them again.

## Later work

- Document the required regenerate flow (copy/uncomment `.dev.vars` → `pnpm --filter @strengthsync/api types`).
- Drop the retired Temporal-era tunnel vars (`WORKFLOW_*`, `INTERNAL_API_SERVICE_SECRET`) from `.dev.vars.example` and the workflow proxy once the migration is complete.
- Consider CI/local guard so `types` can’t silently strip secrets, or commit a stable Env extension that doesn’t depend on a local `.dev.vars`.
- Align `.dev.vars.example` with whatever becomes the source of truth for typed secrets.
