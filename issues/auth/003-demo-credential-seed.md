## What to build

A way to give the seeded demo athlete a credential, so that the training data
already in the repository stays reachable once sign-in exists.

- A password-hashing script placed alongside the existing contract generator and
  run the same way. It takes a password and prints a stored-format hash produced
  by the project's own password module — not a reimplementation, so the output is
  guaranteed to verify.
- A committed seed file that inserts a credential row for the seeded demo
  athlete, using a hash generated by that script. It is idempotent in the same
  style as the existing seeds.
- The dev password is documented next to the seed. It is deliberately committed:
  the demo athlete owns the only plan, weeks and history in the repository, and
  without a credential the tracker and history screens become unreachable by hand
  once authentication lands.

This slice does not change how seeds are invoked — that is the following slice.

See the "Seeds, scripts and documentation" section of the parent PRD, and the
committed-credential note in "Further Notes".

## Acceptance criteria
